## Behavior implemented

- The signed-in admin gets a **Knowledge sources** workspace. It accepts text PDFs, UTF-8 TXT/Markdown documents (5 MiB maximum), one configured-host HTTPS page, or a direct HTTPS `.xml` sitemap URL. The UI chooses `staff` or `admin` visibility. It shows recent jobs, per-page sitemap jobs, aggregate progress, safe errors, registered sources, bounded retry, source removal and document replacement with the same source ID. Polling occurs every four seconds.
- A removed website page remains a revoked registration. The admin can now click **Restore** after its removal job completes; `POST /api/v1/ingestion/sources/{source_id}/restore` queues a fresh URL fetch under the same source ID and visibility. A direct Add page request still refuses the tombstone with a helpful message. The source stays inactive throughout extraction, embedding and vector cleanup; the worker activates it only with the verified ready generation. A failed restore remains hidden and can be retried. A failed removal must complete its cleanup before restoration.
- `POST /api/v1/ingestion/sitemaps` is admin-only, reads at most 4 KiB of JSON after authentication, and is rate-limited to three submissions per user per minute per API process. It returns HTTP 202 and a parent job ID in worker mode. The E3 PostgreSQL worker discovers pages, persists the discovered URL list before fanout, then enqueues deterministic child page jobs. A failed parent retry reuses that saved list and deduplicates existing children. Parent completion means **queueing completed**, not that every page was indexed. `GET /jobs/{id}` reports child counts; admin-only `GET /jobs/{id}/pages` lists child status and URLs in pages of at most 100.
- Sitemap discovery and page extraction run in a 512 MiB, 20 CPU-second, 30 wall-second parser subprocess without database/model credentials. Discovery accepts at most 1,500 eligible pages, 16 XML files, nesting depth two, 5 MiB per XML and 12 MiB total XML. Direct HTTPS, configured public host/IP, pinned TLS hostname, same-host XML/page URLs, robots rules, no redirects/compressed responses, and descriptive Sardars paths constrain network access. XML DTD/entities are rejected. Page requests observe a minimum 0.5-second pause and robots delays up to 10 seconds. Pages without usable descriptive text fail individually.
- Existing import publication preserves URL-derived source IDs, provenance, source visibility, original bytes and checked Qdrant generations. The application rechecks the admin submitter while queueing and processing sitemap children; changing that role or disabling the account stops unpublished work. Retrieval still checks current source permissions. Removal hides a source before vector cleanup. PostgreSQL remains authoritative for SKU, price and stock.
- The schema migration expands job operations to `crawl` and adds an indexed `parent_job_id`; it does not clear existing jobs, products, users, conversations or vector data. The original single-file and single-URL API continues to work. A browser can replace an uploaded document only under the same source visibility and format rules.

## Operational limits

The local worker is serial. A large sitemap may take hours depending on robots delays, extraction and embeddings; parent progress does not estimate time. There is no crawl cancel control or automatic deletion of URLs removed from a later sitemap; remove obsolete registered sources explicitly. Parser and index failures are visible on each job, with a maximum of three attempts. The source list shows 100 entries per page and recent top-level jobs are capped at 50; older jobs remain accessible by ID through the API. Scanned PDFs require OCR; DOCX is unsupported. URL imports require an allowed host in configuration. The source index contains descriptive claims; it does not certify current price, stock, policy or delivery promises.
