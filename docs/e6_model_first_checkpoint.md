# E6 model-first prototype follow-up (2026-10-22)

## Behavior and decision

The developer requested that ordinary `/chat` and `/ask` turns reach a local LLM even if retrieval finds no usable company text. The current path retrieves a small role-authorized RAG set, lets the model request at most two bounded read-only calls, and asks the model for a final answer. A greeting skips retrieval but still reaches the model. PostgreSQL remains authoritative for catalog SKU, price and stock; the application executes and renders those facts, rather than accepting model-written values. Product category lists now use a separate, role-filtered, bounded PostgreSQL read because a live RAG answer incorrectly treated internal FAQ editorial tags (`P004`–`P007`) as categories. The category question still reaches the LLM, while the application renders the exact catalog labels.

This supersedes the E6 application-first router for the current HTTP endpoints. The E6 routing report and its pass counts describe the earlier path only. The original corpus, 100-word/15-overlap chunks, embedding model, Qdrant collection, PostgreSQL product rows and named volumes were not reset or reindexed.

The already-installed `qwen3:0.6b` is used for interactive `/chat` and `/ask`; the historically selected 4B model remains configured separately for earlier answer/evaluation paths. On this CPU stack, the 4B greeting took 180.5 seconds and a company question reached the 300-second HTTP deadline. A direct 0.6B greeting probe took 7.8 seconds. The smaller model is an interactive-latency experiment, not a quality sign-off.

## Live sample and diagnosis

The first optimized authenticated `/chat` sample returned a natural greeting in 3.1 seconds; “what is Sardars?” returned a cited About Us answer in 38.7 seconds; and “can you give me some products of Bongio” returned three PostgreSQL catalog matches in 55.1 seconds. The cited company excerpt supported the sampled overview claims. Two returned Bongio product handles were independently checked against the SQL vendor field.

Authenticated `/ask` checks found more uneven quality: the customer-opinion question first took 58.7 seconds and omitted a citation while softening the uploaded FAQ's price criticism. After a more explicit citation/qualification prompt, a retry took 42.2 seconds and cited two FAQ excerpts, but still omitted the price criticism. The Rawalpindi address question took 38.2 seconds and cited a matching authorized Showrooms excerpt. The categories question first returned unrelated products in 82.2 seconds; after disabling that route, it returned uncited internal FAQ tags in 37.6 seconds. Both are answer/routing failures, not evidence that those tags are catalog categories. After adding the catalog category tool, the rebuilt API returned the twelve actual stored labels in 96.6 seconds (HTTP 200). This is a correct data-backed list, but too slow for a responsive chat, and one label contains the catalog's original misspelling, `Concleaed Tanks`. The temporary authentication session was removed after the probe; the list did not require a corpus or product update.

## Boundaries and open quality work

Application authentication, source visibility, current source-registration checks, strict tool inputs, capped excerpts/tool calls/output and request deadlines remain in force. Untrusted source and tool text cannot grant permissions. The model can answer a general question without company evidence, but unsupported Sardars-specific claims are still possible: the current output mapping verifies that citation numbers refer to supplied excerpts, not that every cited claim is entailed by them. The 0.6B model's first review answer and category failures demonstrate that risk. The old E4/E5/E6 evaluation scores cannot be reused as scores for this route. The final backend suite passed **651 tests, with four skipped and one existing Starlette warning**; 67 focused model/tool checks passed. A read after the live check found 991 source registrations and 4,983 product rows, and the temporary login session had been removed. `git diff --check` passed.

Before marking this prototype follow-up complete, rebuild the current-flow case set, independently review a broader sample of generated claims and citations, and decide whether the 0.6B quality/CPU latency trade-off is acceptable. Include greetings, FAQ qualification, sentiment, categories, address, product discovery, exact changing facts, missing evidence, role revocation and injection. E7 or production claims should wait for that result.
