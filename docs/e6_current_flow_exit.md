# E6 model-first follow-up: current-flow exit (28 October 2026)

The current `/chat` and `/ask` path retrieves a small role-authorized company context before a local model turn. A bounded model tool-choice call remains available for questions the application has not already resolved. Explicit product questions use the role-checked PostgreSQL tools even when the model omits a call. Source text and tool results cannot grant permissions. Every normal answer still reaches the local model; when the application has a checked FAQ, company description, or catalog result, it sends only that selected context for a short acknowledgment and renders the checked answer. This avoids letting the 0.6B model overwrite a verified price, stock value, citation or qualification. General education and unresolved company questions remain model-generated.

## Evidence and decisions

The first four-case live diagnostic passed 3/4: a broad Sardars overview cited an unrelated retrieved excerpt and invented business details. A later 14-case automated pass exposed an unsupported return-policy attribution, an injection refusal that offered access to internal material, and a stray general-education citation on manual review. The first five-case open-ended company sample passed only 3/5 automated checks; manual review also found an invented Lahore showroom, an unsupported competitor superiority claim, a copied FAQ metadata block in the history answer, and a brand-list answer replaced by a generic overview. Those problems were real despite some permissive automated checks passing.

The fixes are narrow. The company overview retrieval hint now recognizes “sells,” while the checked overview answer is limited to broad identity questions. Brand-list questions cite only names explicitly present on the authorized About Us page and omit its adjacent promotional claim. Customer sentiment, ratings, address, return guidance, and installation scope use complete qualified FAQ evidence. A second showroom city is described as unverified unless the uploaded FAQ supports a more specific answer; Rawalpindi evidence cannot become a Lahore branch claim. History and unsupported competitor-superiority questions abstain from invented assertions. Product answers remain checked against current PostgreSQL rows; the selected catalog and source evidence passed to the acknowledgment are capped. Model output limits, tool count, retrieval context, timeouts and source rechecks remain bounded. The corpus, embeddings, Qdrant collection and product records were not reindexed or rewritten.

The final read-only 14-case current-flow replay passed **14/14** with **8/8** expected citations/source hits, **2/2** exact PostgreSQL fact checks, **2/2** stock checks, **4/4** declared tool checks and a stable source/product fingerprint. Its median latency was **3.82 seconds** and observed p95 was **26.39 seconds**, driven by the general-education answer. The five open-ended claim cases passed **5/5**, median **4.76 seconds**, p95 **9.60 seconds**. A separate final brand-wording recheck passed **1/1** with a stable fingerprint. Reports: `data/e6_current_exit_2026-10-28.json`, `data/e6_current_claim_final_2026-10-28.json`, and `data/e6_current_brand_recheck_2026-10-28.json` (local ignored data files). Earlier failed reports remain in `data/` for comparison.

I separately read the captured answer and authorized evidence for each cited company case. The About Us page supports the identity and named brands; the uploaded FAQ supports the qualified review, rating, address, installation and other-city answers; the return answer states no verified general window; the competitor and history answers make no unverified affirmative company claim. The product cases have independent SQL comparisons in the evaluator. This is an agent-performed source audit, **not independent human sign-off** or proof that every possible question is grounded. The current 0.6B model is acceptable only for this bounded internal prototype sample; its unrestricted general-education answer was repetitive and may be over-specific. Freeform company answers outside the reviewed sample remain a quality risk, and no business latency target has been set.

The full backend suite passed **679, four skipped** after fixing a test mock to accept the new bounded-output argument. The role-visibility integration test and a revoked-source model-answer test passed; no hidden source excerpt reached a staff prompt in those checks. The rebuilt local API returned `/ready` 200 and anonymous `/ask` 401. This run did not create a new authenticated browser conversation; the live case runner exercised the answer service with trusted local actors, while HTTP authentication and role behavior were checked in backend tests. The backend emitted one existing Starlette deprecation warning.
