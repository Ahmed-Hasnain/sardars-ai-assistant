## Update rule

Update this file when a **major feature or phase milestone is complete and verified**: for example, a working PostgreSQL foundation, local LLM chat, document retrieval, grounded RAG, safe tools, conversation history, or the frontend. Record the behavior, key files/components, verification evidence, limitations, and next major milestone. “Complete” means the intended behavior works end to end, the relevant checks have passed, and another developer can run it using the documented setup. Files or folders existing by themselves do not count.

## Current working implementation

- The Python 3.12 backend has FastAPI/Uvicorn, typed environment settings, SQLAlchemy with psycopg, and a local virtual environment ignored by Git. `.env.example` documents required settings; `.env` is ignored.
- Docker Compose runs PostgreSQL 18 with a persistent volume, a health check, and port 5433 bound to localhost. `backend/app/db/session.py` creates the application engine and session factory.
- `GET /api/v1/health` checks API liveness. `GET /api/v1/ready` runs `SELECT 1` against PostgreSQL and returns HTTP 503 when the database is unavailable.
- Alembic is wired to the same database settings and has an applied baseline revision (`87b27fb5a926`). This baseline contains no business tables; it establishes schema version tracking.
- Ollama runs locally with `qwen3:0.6b` on the developer's Ubuntu laptop. `backend/app/llm/base.py` defines a small chat interface and result/error types; `backend/app/llm/ollama.py` implements it through Ollama's local HTTP API with a timeout, error handling, and available token/latency metrics. Configuration defaults to unloading the model after each request to conserve memory.
- `POST /api/v1/chat` validates the message and uses a conservative deterministic router: clear general education goes to Ollama, while Sardars and ambiguous business questions use the same registered-source answer path as `/ask`. Its response includes `route`, numbered source metadata for company answers, and available model metrics. `company_data_verified` remains false because source authorization does not prove that changing business facts are current. Model/retrieval failures return HTTP 503.
- `backend/tests/test_health.py` and `backend/tests/test_chat.py` cover six health and chat cases. `backend/requirements-dev.lock` records exact installed development dependencies, and `README.md` describes local setup, tests, and chat.
- The project owner supplied the public website sitemap and company profile text. `data/source_inventory.md` records their provenance, `data/sources/company_profile.md` stores the pasted profile, and `backend/app/ingestion/public_site.py` discovers public sitemap links and extracts reviewable page, article, and product-description records. It checks robots rules, restricts URLs to the site and descriptive paths, limits each run, waits between requests, and leaves product offer data out of extracted text. Output records carry source identity, public visibility, fetch time, content checksum, and pending review status.
- The developer pulled `qwen3-embedding:0.6b` in local Ollama and verified that `/api/embed` returns a 1,024-dimensional vector. Docker Compose runs Qdrant v1.19.2 on localhost port 6333 with a persistent `qdrant_data` volume. Collection `sardars_public_qwen3_embedding_06b_v1` uses 1,024-dimensional cosine vectors and holds three internally authorized seed points.
- `backend/app/ingestion/chunking.py` splits two selected public records into three overlapping word-window chunks. `backend/app/ingestion/index_seed.py` validates the Sardars site URL, embeds the chunks, and upserts them with source metadata, `review_status: approved`, and `prototype_only: false`. `backend/app/retrieval/search_seed.py` embeds a question and supports separate approved and prototype CLI filters, returning scores, text, and URLs. The developer showed approved mode returning three chunks after re-indexing. These remain CLI prototypes, not an authenticated internal API retrieval path.
- `backend/app/rag/answer_seed.py` implements the seed answer path. It uses registered, role-filtered Qdrant results, selects source sentences within an 1,800-character evidence budget, and accepts only extractive cited model text; otherwise it returns an exact sourced sentence. Its numbered citations carry source ID, title, URL, and fetch time. It abstains without citation when no sentence matches, on changing-fact questions, or on obvious numeric/negation conflicts. This conservative lexical gate can miss paraphrases and does not establish general answerability.
- `backend/app/evaluation/run_seed.py` runs four live questions against the approved seed and one synthetic prompt-injection case. It checks supported brand and bathroom-storage answers for expected citations/content, plus uncited abstentions for missing return-policy and current-price facts. The bathroom-storage case exposed a missing answer caused by generic question terms and split product evidence; the answer seed now ignores those generic terms and keeps the neighboring product-name sentence. An injected instruction in a relevant source sentence exposed a cited-answer failure; the answer seed now discards obvious instruction patterns before prompting or falling back to source text.
- `backend/app/db/models.py` and Alembic revision `6a9d2c7e41b0` add users and hashed, revocable login sessions. `backend/app/auth/` provides salted scrypt password hashing, random bearer tokens, per-request user/role checks, and an interactive user-creation command. The first lasting account must be an admin. Login tokens expire after eight hours; logout deletes the session. Admins can list account metadata; staff cannot. The migration was applied to local PostgreSQL; a temporary admin passed a live smoke check and was deleted. The developer has since created one active lasting admin account locally.
- `backend/app/auth/reset_password.py` adds a local password reset command that prompts privately for a replacement and revokes every existing session for the account in the same database transaction. There is no public password-reset API.
- Alembic revision `f34a2d6c91b7` adds PostgreSQL `source_registrations` as the authority for source identity, URL, type, visibility, active status, content checksum, and authorization basis. `register_seed.py` idempotently registers the two owner-authorized public seed URLs; `index_seed.py` requires matching active registrations. Authenticated `/ask`, the grounded-answer CLI, and the live seed evaluation check Qdrant results against PostgreSQL before using their text. Unit tests exercise unknown, disabled, mismatched, and admin-only records; private documents are not indexed yet.
- Both `POST /api/v1/chat` and `POST /api/v1/ask` require a valid bearer token. Company questions use Qdrant's role-aware visibility prefilter and PostgreSQL's source registration check before prompt assembly. An admin-only synthetic source reaches admin answers but is excluded for staff. No actual private document has been indexed. `GET /api/v1/health` and `/ready` remain unauthenticated service checks.
- `scripts/dev.sh` starts PostgreSQL and Qdrant, checks/starts host Ollama, runs FastAPI, and follows their logs in one terminal. Its foreground API and log followers stop on Ctrl+C; Docker containers and Ollama remain running.
- The project owner has authorized the supplied sitemap/site links and company profile for the admin/staff-only prototype at the source level, without individual page approval. This policy is recorded in `PLAN.md` and `data/source_inventory.md` and applied to the three seed points at indexing. General `/chat` answers are ungrounded educational content; company `/chat` answers use the registered public seed. Real private-source ingestion, frontend, and business database schema are not built. Some blog articles discuss prices or promotions; source authorization does not verify those changing facts.

Current request flow:

```text
Browser or curl → Uvicorn → FastAPI → /health → liveness JSON
Browser or curl → Uvicorn → FastAPI → /ready → SQLAlchemy → PostgreSQL → readiness JSON or HTTP 503
Postman or curl → Uvicorn → bearer session/user check → /chat router → general Ollama answer or registered-source grounded answer
CLI prototype → question embedding in Ollama → Qdrant approved-public vector query → ranked chunks with source URLs
CLI answer seed → approved Qdrant chunks → matching source sentences → local chat model or exact sentence fallback → cited answer or abstention
Authenticated /ask → role-prefiltered Qdrant query → PostgreSQL source-registration check → bounded source sentences → numbered citation or abstention
```
